04:20 — An idle worker can hold a restart for 90 s

After the fixes, a restart of the worker pools still took 91 s in some runs. In those runs, one idle worker did not react to the stop signal. systemd waited its 90 s stop limit and then killed the worker. Young pools (20 s old) restarted in 2 to 3 s. A capture loop on the test server now restarts the pools every 75 s and records the stack of any worker that does not stop.

The restart no longer fails because of this, because the restart budget now covers the 90 s stop limit (issue 1). The open question is why the worker ignores the signal.

03:30 — Root causes

Issue 1 and 2. Pilot puts the sites in maintenance mode and starts the backup, update and migrate at once. It does not wait for running jobs. At the end, Pilot restarts web and the workers. A worker that runs a job finishes the job before it stops. systemd lets a unit take 90 s to stop. Pilot gave the complete systemctl restart only 90 s, so one slow worker made the restart fail.

The Frappe Cloud agent does this differently. It puts the site in maintenance mode, then runs bench --site X ready-for-migration again and again for up to 300 s. It continues only when the site has no queued or running job.

Issue 3. Under systemd, Pilot runs Frappe's worker-pool. It merged all worker groups into one pool that listens to every queue. So the counts per queue in the settings had no effect. Lite mode already merges groups on purpose and the UI says so; systemd mode did not.

03:00 — Changes

  • Before a site's backup, before the app update, and before a site's migrate, Pilot waits until ready-for-migration reports no jobs for that site. The limit is 300 s, the same as the Frappe Cloud agent. If the jobs do not finish, the operation goes to needs_attention before the step starts, with the message "still has background jobs after 300 seconds. The step did not start. Retry later." No code or data changes. Pilot skips the wait when the workload is stopped, because then no worker runs jobs.
  • A systemd restart now gets the slowest unit's stop limit (90 s when the unit sets none) plus 120 s to start. Before, it got 90 s in total.
  • Under systemd, Pilot runs one worker pool per worker group, for example worker_pool_default, worker_pool_short, worker_pool_long. A bench with one group keeps the old worker_pool name, so its units do not change. Frappe's scheduler uses a bench-wide file lock, so several pools still run only one scheduler.
