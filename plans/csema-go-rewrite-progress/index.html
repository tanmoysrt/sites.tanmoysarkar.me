UI polish segment (01 Nov 2026)

  • The landing page is at /. The signed-in home is at /dashboard.
  • Auth screens, Ctrl+K search, buttons, cards and focus states use one calm theme with soft neutral surfaces.
  • A flag capture or a finished lesson shows a short celebration.

  • The sidebar has its own surface and a raised active row. Its collapse button is at the bottom.
  • All 765 challenge titles, categories and stories are rewritten. Categories drop from 38 to 15.

  • A user can have many sessions. A session lasts 7 days by default.
  • Browser check: admin, auth and sidebar in light, dark, collapsed and narrow states.

Content and lab cleanup (01 Nov 2026)

Every challenge was checked, fixed or unpublished, and every machine lab was started on a real lab host. Now 384 of 632 challenges and 72 of 152 machine labs are published.

  • Codex (gpt-6-luna, high effort) rewrote all 784 challenges and machines: title, story, hook, objective, known facts, questions, hints, category and tags from a fixed list. A script checked each result: challenge data, file names and links stay the same, flag parts and XP do not change, and no flag is in the text. All titles are unique.
  • 8 challenges with very long flags got short flags taken from the evidence. Each one passed a blind solve.
  • 122 reviewed challenges are now published.
  • Unpublished, with the reason in the log: challenges whose external target is down, challenges that need a private registry login on the player's computer, and a riddle with no known answer.
  • Each machine lab was started on the lab host with the same limits as the agent: 1 CPU and 512 processes. The test checked that each container runs, that each port answers and that SSH greets. It did not solve the labs.
  • Fixed lab specifications: wrong ports on 8 labs and memory that was too low on 2 labs.
  • Unpublished machine labs that cannot run safely or at all: labs that need privileged containers or extra capabilities, labs whose containers must share a volume, broken images and OVA virtual machines.
  • 3 entries without a runnable lab became plain challenges. A plain challenge can now have several flag questions, like a machine.
  • Private registry logins are a setting (lab_registries). Each sync sends them to the agents, and the agent uses only these logins to pull images.
  • The lab panel is simpler: one start button, one short starting message. Opening a machine page now starts its lab when the player has time left and no other lab runs.
  • The challenge file viewer shows "Open target" next to "Download" in its header.

What works now

  • One binary (16 MB with the UI) serves /api, /files and the embedded Nuxt app. Unknown paths get 200.html.
  • AutoMigrate creates all 23 tables on the local MariaDB 11.8. A second start changes nothing.
  • Sign up, verify mail (through the outbox to Mailpit), log in by email or username, many sessions per user, forgot and reset password, change password, log out.
  • A real Django pbkdf2_sha256 hash logs in and is replaced with argon2id.
  • A cookie request that changes data from another origin (for example a lab site) gets 403.
  • progress.Record is the one writer of users.xp. Event rows never change it.
  • Content import from the Postgres copy: 43 paths (27 published), 752 modules, 434 activities, 763 challenges (367 published), 4 plans, the 30 ranks and the onboarding survey. 2,832 content files copied.
  • The old flag hashes work: 30 flags found in the old lab sources match their stored HMAC hashes with the copied pepper.
  • Practice: challenge list with filters, detail, flag submit (machines with several flags), hints in order with XP cost.
  • Learn: paths, lessons, quiz grading, module completion with XP, path certificates with a public check.
  • Teams: create, invite, join request, join code, accept, remove, owner transfer, member limit.
  • Settings table with typed values, defaults in code, admin list and PATCH.
  • Labs: a host becomes ready through the admin API. A real imported private image runs with an attack box. The browser terminal executes commands through the core and agent.
  • A second session cannot reach the first session, host SSH or the internet. Stop removes the session containers. An agent restart keeps the existing lab containers.
  • Zero-downtime upgrade with tableflip on SIGHUP (not yet tested under load).
  • The browser makes no request to a third-party host. Inter and Lucide icons are bundled.

Decisions to review

I made these choices without asking. Each one is easy to change.

  • Echo v5 (v5.4.4, stable) instead of v4.
  • Module path is csema.
  • OAuth without a library. The Google and GitHub code flow uses the standard library only. The provider URLs are in code, because the providers fix them.
  • User tiers are free, prime, elite. The old basic becomes free at migration.
  • Challenge difficulty keeps the old 4 values: easy, medium, hard, expert.
  • Extra columns not in the ERD: paths.tier (prime and elite paths), plans.features and plans.position (the pricing page reads them), lab_sessions.password (SSH gateway), subscribers.status = pending (double opt-in), mail_outbox.headers (one-click unsubscribe), users.disabled.
  • Technical constants stay in code: drain timeout (30 s), mail retry (5 attempts), argon2id cost, DB pool size. Business values are in settings: session days, token lifetimes, minimum password length, auth rate limit, body limit, ranks.
  • Ranks default to one rank in code. The content import will store the 30 current ranks in the settings table.
  • Machine flags keep the old questions: one flag part for each question, each with its own XP. The last part marks the machine solved with 0 XP, so XP is not counted twice.
  • Activity XP is 0. As before, only module completion gives XP. A quiz keeps its score.
  • Global teams: a user can be in more than one team (as before). Team XP is the sum of the members' XP.
  • tygo is pinned as a Go tool (go tool tygo generate).
