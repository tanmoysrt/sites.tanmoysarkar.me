D1 App/database RAM split The split is hard-coded: MariaDB gets about half of the RAM (/2 and _MAX_HOST_MEMORY_SHARE = 0.5 in pilot/core/mariadb_memory.py). Gunicorn workers do not follow the host size. An optional memory_share (0.2 to 0.8, default 0.5) in [mariadb] of common_config.toml, used by the sizing and the Admin limits; a slider on the database settings page. See the mockup below. Small backend change, one UI control (needs mockup approval) Done. [mariadb] memory_share and a Memory split row in Settings, Database. Checked on VM: 65%, then back to 50% from the dialog (MemoryMax and pool as previewed).
D2 socket.io exposed Frappe's socket.io listens on *:9000 and answers from the internet. It bypasses nginx and the WAF. No host firewall is on by default. Use Frappe's socketio_uds (Unix socket) and proxy nginx to it, or bind to 127.0.0.1. Unit and nginx template change, patch for existing benches Done. systemd benches serve Node realtime on config/socketio.sock; nginx proxies to it; patch serve_realtime_on_unix_socket. Checked on VM: port 9000 closed, WebSocket 101 through nginx, restart after kill -9.
D3 Rename and Central Pilot sets the new name as primary when Central asks (make_primary). Central keeps the auto-routed site-xxxxx host as the record name and its URL. The image runs setup central --site-pattern without --redirect, so the alias is served, not redirected. Central: switch the shown URL to rename_target after the rename task succeeds. Pilot: when redirect is on, redirect the alias to site.primary, except /api/method/ping, which Central probes. Central change plus a small nginx change Done. Pilot keeps /api/method/ping on redirecting aliases; Central records renamed_at and shows the customer hostname (worktree fix/site-primary-url, 70 Central tests pass).
D4 Cloudflare proxy A domain behind the orange cloud fails the "points here" DNS check (409). Flexible SSL loops on the HTTP-to-HTTPS redirect. Client IPs are Cloudflare's. Accept Cloudflare IP ranges in the DNS check with a warning; an optional proxy.cloudflare setting for set_real_ip_from + CF-Connecting-IP; document "Full (strict)". Medium Done. Optional [proxy] cloudflare; Cloudflare addresses pass the DNS check with a warning; docs say Full (strict). Setting is in config, not in the UI. Checked on VM with real DNS; spoofed header not trusted.
D5 Certificate renewal Pilot never calls certbot renew. Debian and Ubuntu enable the certbot timer; Fedora and Arch do not, so certificates can expire there. No expiry alert. A Pilot user timer that runs renew and a reissue sweep, plus a notification under 14 days. Medium Done. Daily pilot-certificates.timer renews and alerts under 14 days. Checked on VM.
D6 Uninstall (#567) Uninstalling an app from its last site also removes it from the bench (documented, surprising). Keep the app on the bench; remove-app is the only removal. Accept, or restart MariaDB once at boot when the host grew (issue #528 asks for no automatic restart). Small Done. pilot-mariadb-sizing.service re-sizes before each MariaDB start when memory changed by 100 MB or more. Checked on VM: 4 GB to 2 GB resize, boot in 26 s.

Test guide and proposed commits

Test setup

Use one disposable Ubuntu 24.04 VM. Do not use a production host.

  1. Install Pilot from the branch in development mode: curl -fsSL <install.sh> | bash -s -- --dev, then put the branch checkout in ~/pilot.
  2. Create two benches: version-16 with ERPNext and develop in lite mode. Run pilot setup production on both with an admin domain.
  3. Use a wildcard DNS name that points to the VM, for example *.ip-<a-b-c-d>.swiftwave.xyz. Use the Let's Encrypt staging CA for repeated tests (server = https://acme-staging-v02.api.letsencrypt.org/directory in /etc/letsencrypt/cli.ini).
  4. After each code change, copy the changed files to the VM and restart the Pilot services. Run pilot admin run-patches when a patch was added.
