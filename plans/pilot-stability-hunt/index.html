Decisions needed

These items need an owner's decision. Each one changes a feature, a deployment layout or a public surface, so nothing is built yet.

# Topic What we found Proposal Cost
D1 App/database RAM split The split is hard-coded: MariaDB gets about half of the RAM (/2 and _MAX_HOST_MEMORY_SHARE = 0.5 in pilot/core/mariadb_memory.py). Gunicorn workers do not follow the host size. An optional memory_share (0.2 to 0.8, default 0.5) in [mariadb] of common_config.toml, used by the sizing and the Admin limits; a slider on the database settings page. See the mockup below. Small backend change, one UI control (needs mockup approval)
D2 socket.io exposed Frappe's socket.io listens on *:9000 and answers from the internet. It bypasses nginx and the WAF. No host firewall is on by default. Use Frappe's socketio_uds (Unix socket) and proxy nginx to it, or bind to <vm-ip>. Unit and nginx template change, patch for existing benches
D3 Rename and Central Pilot sets the new name as primary when Central asks (make_primary). Central keeps the auto-routed site-xxxxx host as the record name and its URL. The image runs setup central --site-pattern without --redirect, so the alias is served, not redirected. Central: switch the shown URL to rename_target after the rename task succeeds. Pilot: when redirect is on, redirect the alias to site.primary, except /api/method/ping, which Central probes. Central change plus a small nginx change
D4 Cloudflare proxy A domain behind the orange cloud fails the "points here" DNS check (409). Flexible SSL loops on the HTTP-to-HTTPS redirect. Client IPs are Cloudflare's. Accept Cloudflare IP ranges in the DNS check with a warning; an optional proxy.cloudflare setting for set_real_ip_from + CF-Connecting-IP; document "Full (strict)". Medium
D5 Certificate renewal Pilot never calls certbot renew. Debian and Ubuntu enable the certbot timer; Fedora and Arch do not, so certificates can expire there. No expiry alert. A Pilot user timer that runs renew and a reissue sweep, plus a notification under 14 days. Medium
D6 Uninstall (#567) Uninstalling an app from its last site also removes it from the bench (documented, surprising). Keep the app on the bench; remove-app is the only removal. Keep the old behavior behind an optional flag. Small, changes default behavior
D7 Marketplace escape hatch A marketplace app follows registry releases only; a developer's branch with no release never gets updates. Fall back to the branch tip when the registry lists no release for that branch, or an opt-in per app. Small
D8 Bench parity No pilot update, drop-site, domain, switch-branch, pip, backup schedule or renew-lets-encrypt CLI. wkhtmltopdf is not installed. Thin CLI commands over the existing core and tasks, in priority order of the parity table. Medium
D9 MariaDB pool after upsize innodb_buffer_pool_size_max is read-only, so after an upsize the larger pool waits for the next MariaDB restart. Accept, or restart MariaDB once at boot when the host grew (issue #528 asks for no automatic restart). Small
D10 pilot restart exit code pilot restart on a development bench or an incomplete production deployment prints guidance and exits 0, so a script cannot tell that nothing restarted. A fix was built and then reverted after review, because scripts may rely on exit 0. Exit 1 in a later release with a release note, or add an optional --strict flag. Small
D11 Source build on small hosts A 2 GB host without swap cannot build Helpdesk from source: the build cap stops it cleanly. But the failed build's yarn install rewrote a tracked yarn.lock, and Pilot counts that as a source change, so it then refuses the prebuilt assets for that app too. Freeze the lockfile during Pilot's installs, or ignore a yarn.lock that only Pilot's install changed. Also #572 (swap during builds). Small to medium
D12 Stranded task A crash between the worker marking a task running and writing process.json leaves the task running forever and its resource keys blocked. Reconcile every running task, not only those with process.json. Small
D13 Concurrent nginx changes Two benches can regenerate the shared nginx config at the same time. With the new rollback, one bench's rollback could overwrite the other's accepted file. There was no host-wide lock before either. A host-wide nginx lock around generate, validate and reload. Small

Plan and status

Goal

Make Pilot stable, correct and light on resources for production use. Find bugs on a real VM, fix the small ones, and record every finding. Test with Frappe version-16 and develop. Bug fixes only: no new features unless a bug needs one.

Ground rules

  • Base: latest develop, local branch fix/bughunt. Nothing is committed or pushed.
  • Test host: one Ubuntu 24.04 VM (1 vCPU, 4 GB RAM, no swap at start). It may be resized up and down to test tuning. Disk stays the same.
  • Domains: *.ip-<a-b-c-d>.swiftwave.xyz wildcard DNS, plus the Atlas auto router for the domain-provider TLS tests.
  • Every finding gets a log entry: what failed, the root cause, the fix (or proposal) and how it was checked.
