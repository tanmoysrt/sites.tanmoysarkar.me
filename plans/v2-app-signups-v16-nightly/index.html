V2 app sign-ups on Frappe v16 and nightly

On V2, users can sign up for ERPNext, CRM, Helpdesk, Learning, Gameplan and Builder. Pilot must install each app on a Frappe v16 bench and on a nightly bench. This plan lists the branch to use for each app and Frappe version, the release pipeline for each branch, and the checks we will do on Pilot.

Rules: test the latest commit of each branch, not a marketplace release. Fix each problem we find, in Pilot or in the app repository. Each branch must build prebuilt assets and must open a release PR in frappe/marketplace.

Updated 2026-11-17. Data comes from each repository on GitHub on that date. Nightly means Frappe develop, version 17.0.0-dev.

3. How a release gets to Pilot

  1. A push to a release branch runs on_release.yml. semantic-release makes a chore(release): commit and a GitHub release.
  2. assets.yml calls Pilot's app-assets.yml. It builds the frontend for the commit and uploads the archive to the GitHub release assets-<branch>. Pilot downloads this archive, so the bench does not build the frontend.
  3. After a release commit, the job calls frappe/marketplace/.github/workflows/publish-release.yml. It opens a PR that adds the commit to apps/<app>.json.
  4. The marketplace check installs the app on a real bench. If it passes, the PR merges, and Pilot can offer the release.

5. Checks on Pilot

We do each check on two fresh benches: one with Frappe version-16 and one with Frappe develop. We install each app from the latest commit of the branch in section 2. We do not use the marketplace release.

#CheckPass when
C1Version rangePilot accepts the app's Frappe range for the bench. This includes -dev bounds such as <=17.0.0-dev and >=17.0.0-dev.
C2get-appPilot clones the branch at the head commit. The Python install works on Python 3.14.
C3Required appsPilot finds the required app (whatsapp, telephony, payments), picks the branch that fits the bench, and installs it first.
C4Prebuilt assetsPilot downloads the assets-<branch> archive for the head commit and checks its sha256. It does not build the frontend on the bench.
C5Asset build fallbackIf no archive exists, Pilot builds the frontend on the bench and the build passes.
C6New site with the appnew-site with the app installs with no error. The required apps are installed too.
C7MigrateA second migrate on the site passes and makes no changes.
C8App UIThe app page loads with no console error and no missing asset (404): /app, /crm, /helpdesk, /lms, /g, /builder.
C9V2 sign-upThe V2 sign-up for the app makes a site, and the user can log in and see the app.
C10UpdateAfter a new commit on the branch, Pilot finds the update, pulls it, gets new assets and migrates.
C11Marketplace releaseThe release PR for the branch passes the marketplace check and merges.

8. Order of work

  1. Make two fresh benches on the test server: Frappe version-16 and Frappe develop, Python 3.14.
  2. Do C1 to C8 for each app on both benches. Record each result in section 6.
  3. For each failure, find the root cause. Fix it in Pilot with tests, or open a PR in the app repository. Add the problem to section 7.
  4. Fix the release pipeline problems P1, P2, P3, P7 and P8, so each branch has assets and a merged marketplace entry (C11).
  5. Do C9 (V2 sign-up) and C10 (update) after the install checks pass.
