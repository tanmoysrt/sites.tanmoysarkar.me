CSEMA learning content rewrite

Plan to replace every learning lesson with one presentation format. Status: proposed, 6 Nov 2026. Counts come from the local database and the files directory on the same day.

Why we rewrite

CSEMA lessons use seven formats today. Each format has its own player, look and quality. Some lessons have a narrated deck, some have Marp slides, and many have only a short write-up. A learner gets a different lesson experience in each path.

The goal is one format for all lessons: a Rabbit presentation. Rabbit is the CSEMA presentation tool. A deck is data, one player shows all decks, and voice audio drives the timing. Activities (quiz, code, shell and challenge) stay outside the deck, in their own section of the lesson.

  • Write-up: the lesson has only text in the database, with no deck. 267 of the 326 write-up and video lessons have fewer than 150 words.
  • Scene + voice: a scene JSON deck with recorded voice. This format is the closest to Rabbit.
  • Marp: static slides with custom scripts and no voice. The 89 Marp decks have about 707 slides.
  • HTML page: a hand-written page, often with interactive parts.
  • Scenario: a network scenario on an outside host.
  • Video: an MP4 file. All 29 are in the Cloud Security path.
  • Canvas film: a hand-coded animation with voice in the page. All 14 are in the AI path.

Where the work lives

All work goes in var/learn-rewrite/ in the CSEMA checkout. The folder is outside the main repository, because content does not go in the code repository. It has its own local Git history, so each lesson change has a diff and can be undone.

var/learn-rewrite/
  PROGRESS.md                      status of every lesson
  01-active-directory-fundamentals-zero-to-enterprise/
    01-introduction-to-active-directory/
      source.json                  old lesson: body, activities, old deck address
      deck.rabbit.yaml             new deck (added during the rewrite)
      media/                       new images and SVG
      audio/, dist/                voice and build output, not in Git
    02-domains-forests-and-trees/
  02-introduction-to-ai-systems/
  ...

The number at the front of each folder sets the order. Old deck files stay in var/files/learning/presentations/. source.json only points to them.

How one lesson moves

  1. Read source.json and the old deck.
  2. Codex (gpt-6-luna, high effort) rewrites the lesson text and narration.
  3. Write deck.rabbit.yaml and its media with the Rabbit skill.
  4. Run the Rabbit audit. Make the voice audio.
  5. Check the activities against the new deck.
  6. The owner watches and listens, then accepts or returns the lesson.
  7. Import the deck and activities into the app.
  8. Set the lesson status in PROGRESS.md: todo, draft, review or done. Commit in the local Git.

Proposed order

  1. Pilot: rewrite three lessons with different old formats: one scene + voice, one Marp and one write-up. The pilot sets the time per lesson and the review checklist.
  2. Published paths: 26 paths and 564 lessons, one path at a time, in folder order.
  3. Paths that are not published: 9 paths and 187 lessons, after the decisions below.

Decisions needed

  • Paths that are not published. Some of these may cover the same subjects as published paths, for example cyber-foundations, networking-basics-fundamentals, operating-systems-basics and python-programming-basics. For each one, rewrite it, merge it into a published path, or drop it.
  • Empty paths. 7 Cloud paths have no lessons. They are not in the folder.
  • Scenarios and videos. The 68 scenarios on the outside host and the 29 videos become decks. Decide if any scenario must stay as a hands-on part in addition to the deck.

How we check success

  • Every lesson in PROGRESS.md has the status done.
  • No lesson uses Marp, a scene JSON deck, a canvas film, a video or the outside host.
  • Every deck passes the Rabbit audit, and the owner accepted it.
